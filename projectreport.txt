CIVICPULSE V2.4: METROPOLITAN SECURITY GRID
==================================================
PROJECT ARCHITECTURE & SYSTEM DOCUMENTATION

1. EXECUTIVE OVERVIEW
---------------------
CivicPulse V2.4 is a high-fidelity, dual-interface municipal management platform designed to bridge the gap between urban citizens and city authorities. Operating under the "Metropolitan Security Grid" aesthetic, the system provides a cinematic, data-driven environment for reporting infrastructure issues (potholes, streetlights, drainage), tracking resolution progress in real-time, and managing city-wide maintenance operations.

The platform leverages AI for report prioritization, real-time spatial analysis for hazard-aware navigation, and a gamified reputation system to encourage civic participation.

2. CORE FUNCTIONAL MODULES
--------------------------

A. CITIZEN INTERFACE (CITIZEN NODE)
- Intelligent Reporting: A guided modal-based system for filing reports with geo-tagging and category selection.
- Operational Records: A personalized dashboard to track active and resolved reports with "Intelligence Feed" (comments).
- Reputation Engine: A tiered XP system (Citizen, Contributor, Guardian, Ambassador) that rewards users for high-priority reports and community verification.
- Hazard-Aware Navigation: A MapView that computes alternative routes using OSRM, highlighting hazard zones (unresolved issues) and calculating "Hazard Exposure" scores for each path.

B. AUTHORITY INTERFACE (COMMAND CENTER)
- Operational Queue: A centralized mission-control dashboard for managing reports by priority and SLA status.
- Personnel Dispatch: An integrated workflow to assign verified field personnel to specific issues with real-time status tracking.
- System Analytics: High-level KPI monitoring (Active Issues, Resolution Rate, SLA Performance).
- Command Map: A global view of city infrastructure health, personnel location, and high-density issue clusters.

3. TECHNICAL STACK
------------------

FRONTEND ARCHITECTURE:
- Framework: Next.js 15+ (App Router)
- Language: TypeScript
- Styling: Tailwind CSS (Custom "Metropolitan" design system)
- Animations: Framer Motion (High-performance cinematic transitions)
- Icons: Lucide React
- UI Components: Radix UI primitives with custom glass-morphism overlays

BACKEND & INFRASTRUCTURE:
- Runtime: Node.js
- Database ORM: Prisma
- Database: PostgreSQL (Relational mapping of Users, Reports, and Departments)
- Authentication: NextAuth.js (JWT-based session management with role-based RBAC)

GEOSPATIAL & AI:
- Mapping Engine: Leaflet.js
- Routing API: OSRM (Open Source Routing Machine)
- AI Integration: Ollama (Local AI inference for report prioritization, severity analysis, and content moderation)

4. DATABASE ARCHITECTURE (PRISMA SCHEMA)
----------------------------------------
- User: Core authentication entity (Citizen vs. Authority roles).
- CitizenProfile: Tracks reputation XP, tier status, and user-filed reports.
- Report: Central entity containing geolocation data, category, priority scores, and status lifecycle (OPEN to RESOLVED).
- Department: Organizes reports by municipal sector (PWD, Transportation, etc.) with specific SLA requirements.
- Personnel: Tracks field workers available for assignment.
- Assignment: Links Personnel to Reports for accountability.
- Interaction Entities: Votes and Comments for community-driven verification.

5. KEY SYSTEM LOGIC
-------------------

A. PRIORITY SCORING ENGINE
The system calculates a "Priority Score" (0.0 to 1.0) based on:
- AI Analysis: Ollama evaluates the text description for urgency.
- Community Weight: Upvotes from verified citizens.
- Recency: Time elapsed since transmission.

B. NAVIGATION SAFETY PROTOCOL
When a citizen requests a route:
1. The system fetches alternative paths from OSRM.
2. It performs a spatial intersection check against a 150m buffer of active hazard zones.
3. It renders paths with distinct visual styles (Solid Neon Cyan for Primary, Dotted Magenta for Secondary).

6. SECURITY & RELIABILITY
-------------------------
- SSL/TLS Encryption: Guaranteed via "Secure Tunnel" protocol headers.
- SSR Compatibility: Map components are dynamically loaded with `ssr: false` to prevent hydration mismatches and ensure client-side Leaflet stability.
- Atomic Transactions: Registration and reporting use Prisma transactions to ensure data consistency during complex write operations.

7. VERSIONING & METADATA
------------------------
- Current System Version: V2.4
- Architecture Pattern: Client-Component Wrappers (for SSR safety)
- UI Aesthetic: Metropolitan Dark Grid (Cyan/Magenta/Lime accents)
